TRMNL X — Binance 4H OI & Price Monitor

USDⓈ-M、COIN-M、TradFi Perpetual｜歷史回補｜Mac 測試｜GitHub Actions 全天候更新

Python 3.11+ · 不需要 Binance API Key

先理解這套架構

項目做法
4h 基準每次執行都向 Binance 查最近 55 根 5 分鐘資料，選擇最接近 T−4h 的一筆。
Mac 關機正式更新交給 GitHub Actions；Mac 只用於第一次測試及選配備援。
API 異常整體成功率不足 60% 時不推送，TRMNL 保留最後一次成功畫面。
TradFi 休市仍在完整市場範圍內，但休市期間不進入 movers 排行。
新上市商品不足四小時歷史就排除，不用錯誤基準硬算。

步驟 1：放到正確資料夾

將 ZIP 解壓縮後，把資料夾放在原本 PL 專案旁邊，完整位置建議為：

$HOME/Documents/temnl/trmnl-binance

開啟 Terminal，確認路徑：

cd "$HOME/Documents/temnl/trmnl-binance"
pwd
ls

ls 應該看得到 binance_dashboard.py、trmnl_full_markup.html 和 config.example.json。

步驟 2：建立 TRMNL Private Plugin

  1. 進入 TRMNL 網站的 Plugins／Recipes 頁面。
  2. 建立一個新的 Private Plugin，名稱可填 Binance Perpetual Pulse。
  3. 資料策略選擇 Webhook，儲存一次。
  4. 複製頁面提供的完整 Webhook URL，格式應以 https://trmnl.com/api/custom_plugins/ 開頭。
  5. 進入 Edit Markup，打開 Full 分頁。
  6. 將 trmnl_full_markup.html 的全部內容貼進去並儲存。不要貼到 Shared。
此時預覽可能是空的，因為還沒有送入第一筆資料，屬於正常現象。

步驟 3：設定本機 Webhook

cd "$HOME/Documents/temnl/trmnl-binance"
cp config.example.json config.json
open -e config.json

把第一行的 placeholder 換成剛才複製的 Webhook URL。其他設定先不要改：

{
  "trmnl_webhook_url": "https://trmnl.com/api/custom_plugins/你的完整網址",
  "min_oi_usd": 5000000,
  "oi_rows": 10,
  "price_rows": 5,
  "workers": 64,
  "history_limit": 55,
  "min_success_ratio": 0.6,
  "cache_max_age_minutes": 30
}

保護設定檔：

chmod 600 config.json
chmod 700 binance_dashboard.py

步驟 4：先做不推送的小測試

這會各抽取一部分 UM、CM、TradFi，確認 Binance API 與 4h 計算正常，但不會更新 TRMNL：

cd "$HOME/Documents/temnl/trmnl-binance"
python3 binance_dashboard.py \
  --config config.json \
  --dry-run \
  --max-symbols 30

最後應該看到類似：

OK Binance Perpetuals | 30/30 symbols | UM 10 CM 10 TF 10 | 1750 bytes

步驟 5：第一次全市場推送

cd "$HOME/Documents/temnl/trmnl-binance"
python3 binance_dashboard.py --config config.json

全市場約有數百個商品，需要逐商品抓 OI 與 Mark Price 歷史；依 Binance 回應速度可能需數分鐘。

  1. 看到最後一行 OK Binance Perpetuals 才算成功。
  2. 回到 TRMNL Private Plugin 頁面確認 Web Preview。
  3. 按 Force Refresh 更新 TRMNL 伺服器畫面。
  4. 實體 TRMNL X 仍要等下一次喚醒；Force Refresh 不代表電子紙會立即喚醒。

步驟 6：設定 GitHub Actions（電腦關機仍更新）

6A. 建立 Repository

  1. 在 GitHub 建立 repository，名稱建議 trmnl-binance-dashboard。
  2. 公開 repository 最簡單；程式沒有帳號資料，Webhook 會另外放在 Secret。
  3. 不要把本機 config.json 上傳；專案的 .gitignore 已排除它。

在專案資料夾執行，下方 remote URL 要換成你自己的 GitHub 帳號：

cd "$HOME/Documents/temnl/trmnl-binance"
git init
git add .
git commit -m "Initial TRMNL Binance dashboard"
git branch -M main
git remote add origin https://github.com/YOUR_USERNAME/trmnl-binance-dashboard.git
git push -u origin main

6B. 加入 Webhook Secret

  1. GitHub repository → Settings。
  2. Secrets and variables → Actions。
  3. 按 New repository secret。
  4. Name 填 TRMNL_WEBHOOK_URL。
  5. Secret 貼上完整 TRMNL Webhook URL 後儲存。

6C. 手動測試一次

  1. Repository → Actions。
  2. 左側選 Update TRMNL Binance dashboard。
  3. 按 Run workflow。
  4. 工作變成綠色勾勾，並在 log 看到 OK Binance Perpetuals 即完成。

工作流排程是每小時的 02、12、22、32、42、52 分，也就是每 10 分鐘一次。GitHub 排程可能偶爾延遲幾分鐘，但 4h 計算仍以 Binance server time 為準。

GitHub 可能停用長期沒有 repository activity 的公開 repo 排程。建議每 1–2 個月檢查一次 Actions；如果顯示 disabled，按 Enable workflow 即可恢復。

步驟 7：Mac 排程（選配備援）

GitHub Actions 正常後不一定要開本機排程。若仍希望 Mac 開機時也能補推：

cd "$HOME/Documents/temnl/trmnl-binance"
chmod +x install_mac_schedule.sh uninstall_mac_schedule.sh
./install_mac_schedule.sh

查看執行紀錄：

tail -f "$HOME/Documents/temnl/trmnl-binance/binance_dashboard.log"

取消 Mac 排程：

cd "$HOME/Documents/temnl/trmnl-binance"
./uninstall_mac_schedule.sh
GitHub 與 Mac 同時啟用不會算錯，但可能在接近的時間重複推送。一般建議以 GitHub 為主。

異常時怎麼判斷

訊息處理
TRMNL webhook URL does not look valid重新複製 Private Plugin 的完整 Webhook URL。
Binance rate limited等 5–10 分鐘再跑；不要同時手動啟動多次全市場任務。
Only … symbols succeeded程式刻意不推送，TRMNL 會保留最後成功畫面；稍後重跑即可。
某些 symbols omitted少數新上市、資料不足或暫時 timeout；畫面仍可更新，footer 會顯示省略數。
GitHub Action 紅色打開失敗 job 的 log；最常見原因是 Secret 名稱拼錯或 Binance 暫時 timeout。
Preview 更新、裝置沒更新等待 TRMNL X 下一次 wake；網站 Force Refresh 不會強制喚醒電子紙。

預設資料規則

  • OI 排名：依 OI USD 變動絕對金額，不是 OI 百分比。
  • Price movers：依 Mark Price rolling 4h 漲跌幅。
  • 最低 OI：5,000,000 USD，避免低流動性商品霸榜。
  • COIN-M：將 Binance 回傳的 margin-asset OI value 乘以 Mark Price，換算成 USD 名目值。
  • 歷史容忍：T−4h 前後 15 分鐘內最接近的一筆。
  • 全面失敗：不覆蓋 TRMNL 最後成功資料。
完成後，Mac 是否開機不再影響 TRMNL 的定期更新。
